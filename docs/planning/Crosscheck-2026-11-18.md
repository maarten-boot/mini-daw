## Findings

| # | Sev | Finding | Proposed fix |
|---|-----|---------|--------------|
| CC1 | medium | The Plan says "commands that delete or overwrite files left out of the network set", but only `export` is. From another computer, with the token: `import <file> <folder>` makes a new project tree in any folder the user can write; `open <folder>` opens any project, saves into it from then on, and after repairs copies `project.json` over `project.json.bak`; `record` with `arm` records from the microphone. On Windows, `open \\host\share\x` or `import \\host\x.dawproject …` makes mini-daw connect to that host over SMB, which sends the user's NTLM hash. Different errors ("no such file" / "not a zip") tell whether a path exists. No command reads or deletes an arbitrary file. | From other computers: refuse `import`; refuse `open` / `import` paths that are UNC (`\\…`) or not local; state in Spec and README what a token holder can do (open projects, record). Tests in T-RUN-06. |
| CC2 | medium | `wait 3600` or `wait-for 3600 …` holds the commands channel for up to an hour: every other command, also `stop` and `quit`, gets 409, and only the window can end it. A client that goes away is not noticed. | A `cancel` request (or `stop` / `quit` while busy) ends a running `wait` / `wait-for` at once (`"ok": false, "note": "cancelled"`); from outside, `wait` at most e.g. 600 s. |
| CC3 | low | `RemoteServer::stop()` runs on the GUI thread at close: cpp-httplib's `stop()` closes the listening socket only, and the join waits for open connections, up to 5 s for a keep-alive client and 10 s for one that sends slowly. The window seems to hang. | `set_keep_alive_max_count(1)` (one request per connection) and a read timeout of 2 s; the answers are small. |
| CC4 | low | Every program on this computer may send any command without a token, also `export` (replace any file the user can write). This matters on a computer with more users, or when something forwards a port to 127.0.0.1 (SSH `-L`, WSL2, Docker). The token in `config.ini` is readable by others on Linux (the default umask). | README: say so. Optional `[remote] token_local = true`, which asks for the token also from this computer. On Linux, write `config.ini` as 0600 when it has a token. |
| CC5 | low | `/api/state` uses a one-slot channel: a second state read at the same moment gets 409 "busy with another request", while the Spec says the state can be read while a command runs. | Answer every waiting state request in the frame (a list instead of one slot), or say "one at a time" in the Spec and the text. |
| CC6 | low | Over 64 KB gets cpp-httplib's 413 (and 414 / 431 for long lines and headers), not in the Spec's list. `Content-Type` is compared case-sensitively as a prefix: `Application/JSON` gets 415, and `application/jsonx` passes. Not a security risk, because the Origin check already stops web pages. | Spec: add 413. Compare lower-cased, `application/json` followed by the end or `;`. |
| CC7 | low | Refusal lines in the log carry the request's path (decoded) and method unfiltered, and `echo` from a token holder writes any text: control characters can make a log line look like another. | Replace control characters in text from requests before it goes into the log. |
| CC8 | doc | Plan P25 row "P25a done, P25b planned"; the P25b result row in Tests.md says "T-UI-17 Terms" (T-UI-28); `dist/TESTS.txt` T-RUN-07 M lacks the `instrument`, `arm`, `record` steps of Tests.md; CLAUDE.md `src/app/` list without `remote_server.cpp`; Plan PX row #24; test gaps: a non-loopback `import` / `open`, two state reads at once, closing with a keep-alive client. | Fix the texts; tests with the fixes. |

Not taken up: a slow sender from an allowed network can tie up cpp-httplib's worker threads for 10 s each (only when networks are allowed; the fix for CC3 shortens it).
